# 상품 선정 모델 (selection-model.md)

코드: `server/src/modules/selection/` (`scoring.ts`는 I/O 없는 순수 함수, `service.ts`는 파이프라인). 모든 임계값과 가중치는 settings(`selection.*`)에 있습니다.

## 0. 키워드 자동 발굴(`modules/keywords`, 3일마다)
1. 공급처(도매꾹) 카테고리를 **대분류를 번갈아 가며** 순회합니다. 허용 대분류 기본값은 패션잡화·가구/인테리어·생활용품·스포츠/레저·문구이고, 인증·허가가 필요한 분류는 제외합니다.
2. 각 카테고리의 **인기순 상품명**에서 반복되는 1~2어절 표현과 카테고리 이름을 뽑습니다. 홍보·수량·색상 단어는 제거합니다.
3. **네이버 검색광고 키워드도구**로 실제 월간 검색량·경쟁도를 확인하고 연관 키워드를 수집합니다. 5개씩, 2초 간격으로 조회합니다.
4. 걸러내는 키워드:
   - 검색량 1천~15만 범위 밖
   - 경쟁 '높음'
   - 상표·브랜드
   - 정보성·금융·포털 검색어(추천·후기·카드·홈페이지…)
   - 힌트와 단어가 겹치지 않는 연관어
5. **점수 = 0.5×적정검색량(1만 부근 최고) + 0.35×낮은 경쟁 + 0.15×과거 성과**로 키워드 풀(최대 400개)에 저장합니다.
6. 상품 선정은 매일 **고정 키워드 + 판매실적 키워드 + 점수 상위(7일 내 사용분 제외)**로 12개를 가져갑니다. 결과(통과·등록 수)는 점수에 반영하고, **2회 연속 통과 0이면 자동 일시중지**합니다.
7. 관리자 웹 **후보 > 키워드 풀**에서 고정·사용·제외·직접 추가를 할 수 있습니다.

## 1. 파이프라인
1. 키워드 = (자동 모드) 키워드 풀에서 선택 / (수동 모드) 시드 키워드 ∪ 잘 팔리는 상품의 키워드 ∪ **연관 키워드 자동 확장**
   - 연관 키워드: 네이버 검색광고에서 시드마다 상위 `expandRelatedPerSeed`개
   - 조건: 월 검색량 `relatedMinVolume`~`relatedMaxVolume`, 경쟁도 '높음' 제외, 금지어 제외
2. 키워드별 신호 수집(실패한 신호는 없는 것으로 처리)
   - 월간 검색량(네이버 검색광고, 절대값)
   - 추세: 네이버 데이터랩(권한 있을 때). 없으면 **매일 저장한 검색량의 월별 추이**
   - 구글 트렌드 주간 값(보조, 희소하면 무시)
   - 네이버 쇼핑: 최저가·상품 수·판매처 수
   - 쿠팡 파트너스(선택): 쿠팡 검색 상위 최저가·로켓배송 비율(없으면 최근 7일 값 재사용)
   - 쿠팡 판매량 추정(CSV, 최근 30일)
3. 공급처별 검색(공급가 범위 필터) → 상품 상세 재조회 → 목표 판매가 계산(`pricing.targetPrice`)
4. 하드 게이트 → 점수 → 후보 저장
5. auto 모드: 통과 + 점수 ≥ `autoListMinScore` + 공급처 이미지 재사용 허용 + (`autoListRequiresApiOrder`이면) API 자동 발주 가능 → 상위 `autoListPerRun`개 자동 등록. 운영 상품 수 상한(`listing.maxActiveListings`)을 지킵니다.

## 2. 하드 게이트(하나라도 실패하면 제외)
| 게이트 | 조건 |
|---|---|
| status / stock | 판매중, 재고 ≥ `minStock`(재고를 모르면 통과) |
| relevance | 상품명에 키워드(또는 키워드의 모든 단어) 포함 |
| allowedCategory | (도매꾹) 상품 대분류가 허용 목록 안 |
| moq | 최소 주문 수량 1개(위탁은 낱개 발주) |
| prepDays | 출고 준비일 ≤ `maxPrepDays`(3일). 도착이 늦으면 전환율·판매자 점수 하락 |
| sellerQuality | (도매꾹) 판매자 만족도 ≥ `minSellerScore`(85%). 후기 10건 이상일 때만 판단 |
| supplyPrice | `minSupplyPrice` ≤ 공급가 ≤ `maxSupplyPrice` (기본 2,000~100,000원) |
| trademark | 상품명·카테고리에 `blockedKeywords`(브랜드·"정품" 등) 없음 |
| category | `blockedCategoryKeywords`(의약·건강기능식품·주류 등 인증/금지) 없음 |
| kc | `kcSensitiveKeywords`(전기·충전·어린이…)에 해당하면 KC 인증번호 또는 면제 정보 필수 |
| profit | 목표가에서 순이익 ≥ `minProfitKrw` 그리고 순이익률 ≥ `minMarginRate` |
| competitive | 목표가 ≤ 기준 최저가 × (1 + `competitiveTolerance`). 기준은 **쿠팡 최저가(파트너스) 우선, 없으면 11번가 최저가**. 둘 다 모르면 `requireMarketPrice`에 따름 |

소프트 게이트(표시만): 이미지 재사용 허용, 고시정보 보유, API 자동 발주 가능 여부.

## 3. 점수
각 구성요소를 0~1로 정규화하고, **값이 있는 요소만** 가중 평균합니다(가중치 `selection.weights`).

| 요소 | 식 |
|---|---|
| demand | log10(월간검색량+1) / 5 |
| trend | 데이터랩: (최근4주 평균 − 직전4주 평균)/직전4주 평균. 없으면 검색량 월별 추이: (최근 달 − 직전 1~3개월 평균)/평균. [−1,1] → (x+1)/2 |
| googleTrend | 구글 트렌드 같은 방식의 기울기 → (x+1)/2 (보조, 가중치 0.05) |
| rocketCompetition | 1 − 쿠팡 검색 상위의 로켓배송 비율 (가중치 0.05) |
| competition | 1 − log10(네이버 상품수+1) / 6 |
| priceAdvantage | (기준 최저가 − 목표가) / 기준 최저가 × 5 (최저가보다 20% 싸면 1) |
| margin | 순이익률 / 0.3 |
| supplier | 공급처 평점(없으면 0.7) × 0.7 + (자동 발주 가능 ? 0.3 : 0) |
| coupangSales | log10(추정판매량+1) / 4 (기본 가중치 0 — 추정치라 신뢰도 낮음) |
| profitPotential | log10(개당 이익 × 월 검색량 / 1000) / 6 (가중치 0.2) — `docs/profit.md` |
| fastShipping | 출고 1일 이하 1.0 / 2일 0.6 / 3일 0.3 (가중치 0.1) |
| imageRichness | 이미지 수 / 5 (가중치 0.05) — 이미지가 많을수록 구매 전환 유리 |
| returnable | 반품 가능 1 / 불가 0 (가중치 0.03, 오너클랜) |
| entryBarrier | 1 − log10(상위 경쟁 상품 쿠팡 리뷰 수+1)/4 (가중치 0.05, 리뷰 CSV가 있을 때) |

## 4. 운영 루프(`modules/sync`)
- 등록 후 `zeroSaleDays`(14일) 동안 판매 0건 → 하한가로 1회 인하 → 다시 14일 0건 → 판매종료. 다음 선정 주기에 새 후보로 교체됩니다.
- 재보정(향후): 쌓인 `candidates.signals`와 실제 주문 수로 가중치를 회귀 추정하는 배치를 추가할 수 있습니다(데이터 축적 후).


## 5. 우선순위: 기대 월이익(수요 모델, `selection/demandModel.ts`) — 2026-10-14
게이트를 통과한 후보는 **"올리면 한 달에 얼마를 벌까"** 순서로 등록됩니다.

```
기대 월판매 = 1.5개 × (월검색량/1만)^0.6 × 가격대 × 가격 매력 × 경쟁 × 구매전환 × 브랜드·대량 × 추세 × 학습계수
기대 월이익 = 기대 월판매 × 개당 이익
최종 점수   = 0.5 × 월이익 점수 + 0.2 × 월판매 점수 + 0.3 × 품질 점수(§3)
```
- **가격 매력** = (15,000 / 판매가)^0.8: 9,900원 ≈ 1.4, 15,000원 = 1, 30,000원 ≈ 0.57, 89,000원 ≈ 0.24. 사람들이 부담 없이 사는 1만원대가 기본으로 앞섭니다.
- 고가 상품이 앞서는 경우:
  - 검색량이 훨씬 큰 경우
  - 경쟁이 낮은 경우
  - **실제로 잘 팔린 기록이 있는 경우**: 학습계수가 최대 4배까지 올라갑니다.
- 공급가 범위는 2,000~100,000원입니다(배송비를 포함한 판매가 약 1.1만원부터).
- 비중은 `selection.rankWeights`, 가격 매력 계수는 `selection.model.refPrice`·`priceElasticity`에서 바꿉니다.

| 요소 | 계산 | 근거 |
|---|---|---|
| 가격대 | 같은 키워드로 검색된 공급 상품 중앙가 대비 위치: `exp(−0.7·|ln(가격/중앙가)|)`, 2.5배 넘으면 추가로 절반 | 시장가 API가 없어도 공급처 검색 결과로 "많이 팔리는 가격대"를 추정 |
| 경쟁 | 네이버 검색광고 경쟁정도: 낮음 1.2, 중간 1.0, 높음 0.6 | 광고 경쟁이 높을수록 신규 상품 노출이 어려움 |
| 구매전환 | 0.6 + 0.4 × 평균(빠른 출고, 이미지 수, 반품 가능) | 도착 예정일과 상세 이미지가 전환에 영향 |
| 브랜드 | "3M)", "[브랜드]" 표기면 0.6 | 같은 브랜드 상품을 파는 판매자가 많아 가격 경쟁만 남음 |
| 대량 | 10EA·20개입·대용량팩·업소용이면 0.5 | 개인 소비자 수요가 적음 |
| 추세 | 1 + 0.5 × 검색량 추이 기울기 | |
| 학습계수 | (실제 판매 + 2) / (기대 판매 + 2), 키워드·대분류 기하평균, 0.2~4 | **우리 상품의 실제 판매 기록**으로 보정. 잘 팔린 키워드·분류는 더 많이, 안 팔린 곳은 덜 |

- 키워드 일치(relevance)는 단어 기준으로 판정합니다. 한국어 복합명사는 끝 단어가 핵심이라 "필사노트"는 '노트'로 인정하고 "노트북"은 인정하지 않습니다.
- 분산: 같은 상품의 색상·사이즈 변형은 1개만 올리고, 한 키워드는 동시에 최대 2개(`maxPerKeyword`)까지 운영합니다.
- 계수는 `selection.model`, 비중은 `selection.rankWeights`에서 바꿉니다. 매 실행의 계수는 `selection_runs.model`에 남습니다(docs/data.md).

## 6. 운영 주기(자동 교체)
| 시점 | 동작 |
|---|---|
| 등록 ~ 10일 | 출시 가격(하한 +5%) |
| 10일 이후 | 판매가 있으면 목표 가격으로 올리고, 이후 판매 속도에 맞춰 조정(docs/profit.md) |
| 14일 0건 | 하한가로 한 번 내림 |
| 그 후 10일 더 0건 | 판매종료. 빈자리는 다음 선정(매일)에서 기대 월이익 상위 후보로 채움 |
| 판매 발생 | 그 키워드·분류의 학습계수가 올라가 비슷한 상품이 우선 등록됨. 14일 3건 이상인 키워드는 매 선정에 다시 포함 |
