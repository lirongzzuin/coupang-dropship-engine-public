# 운영 런북 (runbook.md)

## 1. 평소 운영 — 목표 하루 5분

시스템이 자동으로 하는 일(주기는 설정 > 고급 > `schedule`에서 변경):

| 작업 | 주기 | 내용 |
|---|---|---|
| 주문 수집·처리 | 5분 | 새 주문 감지 → 재고·가격 재확인 → 쿠팡 상품준비중 → **API 공급처는 자동 발주** / 아니면 구매 작업 알림, 취소·반품 감지 |
| 송장 회수·배송 추적 | 10분 | 공급처 송장 조회 → 쿠팡 업로드 → 배송중·배송완료 반영, 지연 경고 |
| 가격·재고 동기화 | 60분 | 품절 시 판매중지, 재입고 시 재개, 공급가 상승 시 판매가 인상(하한 엄수), 손실이면 중지 |
| 상품 승인 상태 | 30분 | 쿠팡 심사 결과 반영(승인 → 판매중, 반려 → 알림) |
| 상품 선정 | 24시간 | 시드 키워드 + 잘 팔리는 상품의 키워드로 후보 선정, **auto 모드면 조건 충족 상위 N개 자동 등록**. 판매 부진 상품은 1회 인하 후 종료 |
| 고객문의 | 30분 | 배송 문의는 템플릿 자동 답변, 불만·환불은 초안 + 알림 |
| 정산 대사 | 24시간 | 쿠팡 매출내역 → 주문별 확정 이익, 보관기간 지난 개인정보 파기 |
| 일일 리포트 | 매일 09시 | 텔레그램으로 어제 매출·이익·할 일·키 만료 D-day |
| 감시 | 10분 | 주문 수집이 30분 이상 멈추면 알림, 키 만료 D-14/7/3/1 알림 |

**사람이 하는 일**
- **매일(텔레그램 알림이 올 때만)**
  - 🛒 "구매할 주문이 있어요": API가 없는 공급처 상품입니다. 알림 링크 → [공급처 상품 페이지 열기] → 배송지 [복사] → 결제 → 주문번호 입력(1~2분). 공급처가 송장 API를 주지 않으면 송장도 입력(20초).
  - 🛒 "공급처 결제가 필요해요": 예치금이 부족하거나 결제가 승인 대기입니다. 공급처에서 결제한 뒤 [구매 완료]를 누릅니다.
  - 🚨 예외(품절·마진 역전·한도 초과·송장 지연·취소/반품 요청): 주문 화면의 안내대로 [강행] 또는 Wing에서 취소 처리 후 [취소됨으로 표시]합니다.
- **매주(10분)**
  - 공급처 예치금 충전, 카드 한도 확인
  - 쿠팡 Wing > 판매자 점수 확인(API로 조회할 수 없음)
  - (선택) 쿠팡 판매량 추정 CSV 업로드(작업 화면)
  - 후보 탭에서 이미지 직접 제작이 필요한 우수 후보를 승인할지 판단

## 2. 장애별 대응

| 증상(알림) | 원인 후보 | 조치 |
|---|---|---|
| 공인 IP 변경 | 공유기 재부팅·통신사 | Wing > OPEN API 키 > 허용 IP에 새 IP 추가(최대 10개, 30분 내 반영) |
| 주문 수집이 멈췄습니다 | 쿠팡 키 만료, 공인 IP 변경, 쿠팡 장애, Mac 꺼짐 | ① Mac: `bash ~/dropship/bin/status.sh`, `tail -100 ~/dropship/logs/app.log` (서버: `docker compose logs app --tail 100`) ② Wing에서 키·IP 확인(IP는 최대 10개) ③ 키 재발급 시 `.env` 교체 후 재시작(Mac: `launchctl kickstart -k gui/$(id -u)/com.dropship.app`) ④ 수집이 복구되면 겹침 구간(15분)으로 누락 없이 다시 수집됨 |
| 쿠팡 API 키 만료 D-n | 180일 유효 | Wing > 판매자정보 > 추가판매정보 > OPEN API 키 재발급(만료 14일 전부터 가능) → `.env`의 `COUPANG_SECRET_KEY` 교체 → 재시작 → 설정 > 키 발급일 갱신 |
| 작업 실패: … | 외부 API 오류 | 작업 화면에서 오류 메시지 확인 → [지금 실행]으로 재시도. 일시 오류는 다음 주기에 자동 재시도됩니다 |
| 자동 발주 실패(첫 실패부터 알림) | 공급처 장애·로그인 실패·예치금 부족 | 공급처 사이트 확인. 장애가 길면 설정 > 발주 모드를 `approve`로 바꾸고 직접 구매 |
| 공급처 조회 반복 실패 | 공급처 API 장애 | 같음. 판매중 상품이 품절인지 확인할 수 없으므로 길어지면 **긴급 정지** |
| 429(호출 제한) 로그 | 쿠팡 초당 호출 초과 | 자동 감속(60초)됩니다. 반복되면 설정 > coupang.requestsPerSecond를 낮춥니다(기본 2) |
| 품절 주문 발생 | 공급처 재고 소진 | 상품은 자동 중지됩니다. 고객에게 연락하거나 Wing에서 취소합니다(판매자 귀책 취소는 판매자 점수에 영향) |
| 마진 역전 | 공급가 인상 | 자동 중지됩니다. 손실을 감수하고 보낼지 [강행], 아니면 취소 |
| Mac 꺼짐·재부팅 | 정전·업데이트 | 자동 로그인 + `pmset autorestart`면 켜질 때 자동 시작. 지난 24시간 주문은 자동으로 다시 수집 |
| 이상 동작·대량 오류 | 모름 | 관리자 홈 **[긴급 정지]**: 등록·가격·발주·송장·답변이 모두 멈추고 주문 감지만 계속됩니다 |

## 3. 실운영 전환(`golive.sh`)
1. `bash ~/dropship/bin/golive.sh check` — 조회만으로 준비 상태 점검(텔레그램, 쿠팡 판매자 정보·API, 오너클랜 로그인·주문 권한, 이미지 공개 주소 접속, 보내는 사람, 후보)
2. 오너클랜 예치금 충전(처음 10~20만원). 자동 발주는 예치금에서 결제됨
3. `bash ~/dropship/bin/golive.sh` — 점검 → 쿠팡 등록 사전 점검(임시저장 후 삭제) → `yes` 입력 시 `.env` 백업 후 `DRY_RUN=false` + 모든 `LIVE_*=true` → 재시작
4. 되돌리기: `bash ~/dropship/bin/golive.sh off`(모의 실행). 급할 때는 관리 화면 **[긴급 정지]**
5. 첫 2주: 한도(설정 > 주문: 건당 10만원·일 50만원)를 유지하고 예외 건수·출고 지연·실제 이익 확인 후 조정

안전장치(스위치를 일부만 켜도 실제 주문이 사라지지 않음):
- 실제 쿠팡 상품의 주문인데 `LIVE_FULFILLMENT`/`LIVE_ORDERING`이 꺼져 있으면 **모의 처리하지 않고** "구매 필요"로 넘기고 텔레그램으로 할 일을 보냄
- 송장 자동 등록이 꺼져 있으면 "송장 직접 입력 필요"(Wing)로 알림
- 실등록(`LIVE_LISTING`)만 켜도 실제 쿠팡 상품의 가격·재고·판매중지는 실제로 반영(품절 주문·역마진 방지)
- 오너클랜 결제 대기 → 결제되면 자동 진행, 공급사 취소(품절) → 상품 중지 + 알림, 고객 취소 → 오너클랜 주문 자동 취소(요청)

## 4. 백업·복구
- **Mac 홈서버**: 매일 04시 자동 백업(`~/dropship/backups` 14일 + iCloud Drive `dropship-backups` 30일)
  - 복구: `bash ~/dropship/bin/restore.sh <백업파일.tgz>`
  - Mac 교체: 새 Mac에서 `install.sh` → 예전 `.env` 복사 → `restore.sh`
- **리눅스 서버**: `deploy/backup.sh`(cron), 복구는 `deploy/restore.sh`
- **`.env`의 `PII_KEY`를 잃어버리면 저장된 고객 배송정보를 복호화할 수 없습니다.** 비밀번호 관리자에 따로 보관하세요.
- 복구 리허설(분기 1회): 백업 파일로 다른 위치에 복구해 로그인과 주문 화면을 확인합니다.

## 5. 관리자 계정
- 생성·재설정: Mac은 `bash ~/dropship/bin/admin.sh admin '새비밀번호'`, 리눅스 서버는 `docker compose exec app node dist/cli/create-admin.js admin '새비밀번호'` (OTP 비밀키가 새로 발급됩니다)
- 로그인 5회 실패 시 15분 잠금. 고객 배송지 원문 열람은 감사로그(audit_log)에 남습니다.


## 쿠팡 등록 사전 점검(`bash ~/dropship/bin/verify-listing.sh`)
- 상위 후보 1개를 쿠팡에 **임시저장**(심사 요청 안 함, 고객에게 안 보임)으로 보내 쿠팡이 받아주는지 확인하고 바로 삭제합니다.
- 실측으로 확인한 쿠팡 규칙(2026-10-14):
  - 구매옵션 값에 "상세페이지 참조" 같은 의미 없는 값은 거부됨 → 색상은 "멀티", 사이즈는 "FREE"로 채움
  - 병행수입 값은 `NOT_PARALLEL_IMPORTED`
  - 수량 구매옵션이 없는 카테고리는 묶음 옵션을 구분할 수 없어 1개 옵션만 등록
  - 생성 직후는 "저장중"이라 몇 초 뒤에 삭제됨
