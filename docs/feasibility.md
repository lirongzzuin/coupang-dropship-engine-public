# Phase 0.5 — 타당성 분석 (feasibility.md)

- 작성일: 2026-10-13
- 근거: `docs/research.md`. 표의 [R:…]는 research.md의 해당 절이나 미확인 ID(U1~U12)를 가리킨다.
- 판정 기준
  - **완전자동**: 공식 API만으로 사람 개입 없이 처리 가능
  - **조건부자동**: 자동화 가능하지만 선행 조건(승인·검증·config 입력)이 필요하거나 일부 예외는 사람이 처리
  - **반자동**: 시스템이 준비·판단 보조까지 하고 최종 실행은 사람이 함
  - **불가**: 허용된 수단(공식 API)으로 구현 불가

## 2. 단위 경제성 시뮬레이션

### 2-1. 손익 공식 (일반과세자, 공급처가 세금계산서 발행, 과세 상품 기준)

모든 금액은 VAT 포함 현금흐름으로 계산한다.

```
S  = 판매가(고객 결제액, 무료배송 상품으로 판매)
C  = 공급가(VAT 포함)
D  = 공급처 배송비(VAT 포함) — 가정 3,000원
c  = 쿠팡 판매수수료율(VAT 별도) → 실제 차감 = c × 1.1      [R:2-2, 정산 API serviceFeeVat]
r  = 반품 충당률(판매가 대비) — 가정 3%
결제수수료 = 0 ("결제수수료를 이중으로 부과하지 않습니다")      [R:2-2]
납부 VAT = (S − C − D)/11 − 0.1·c·S                            (매출세액 − 매입세액 − 수수료 매입세액)

순이익 P = S − C − D − 1.1·c·S − r·S − [(S − C − D)/11 − 0.1·c·S]
        = S·(10/11 − c − r) − (C + D)·10/11

손익분기/목표 판매가:
  목표 순이익 P   → S = (P + (C + D)·10/11) / (10/11 − c − r)
  목표 순이익률 m → S = (C + D)·10/11 / (10/11 − c − r − m)
```

- 수수료 반영 방식은 정산 API 샘플(판매가 300 → 수수료 22 + VAT 2 → 정산 276)과 같다.
- 월 서비스이용료 55,000원(U3, [2차])은 월 100건 기준 **건당 550원**으로 배분한 열을 따로 표시했다.
- 고객 부담 배송비 모델(유료배송)은 배송비 수수료 3.3%(U3)가 붙으므로 config로 분리한다.

### 2-3. 해석

1. **공급가 1만원 이하 저가 상품은 구조적으로 불리하다.** 배송비 3,000원이 고정이라 손익분기 판매가가 공급가의 **1.5~1.9배**다. 같은 공급처 상품을 수많은 위탁 셀러가 동일상품으로 등록하는 환경(아이템위너 경쟁)에서는 이 가격으로 노출을 얻기 어렵다.
2. **공급가 2~5만원 구간**은 손익분기 배수가 약 1.25~1.3배로 내려와 여지가 있다. 대신 반품 1건의 손실(왕복 배송비 약 6,000원과 상품 회수 리스크)이 커진다.
3. **반품 충당률 민감도**: r이 3%에서 8%로 오르면, 공급가 2만원·수수료 10.8% 상품의 손익분기 판매가는 27,200원에서 **약 29,000원(+6~7%)**이 된다. 반품률이 높은 카테고리(의류·사이즈)는 게이트에서 제외할 것을 권고한다.
4. **"필요 판매가 ≤ 시장 경쟁가" 게이트는 대부분의 위탁 상품을 걸러낼 것으로 예상된다.** 쿠팡 경쟁가를 API로 확인할 수 없으므로 초기에는 네이버 최저가를 대리 지표로 쓰고, 등록 후 Wing에서 아이템위너 여부를 수동으로 확인해야 한다(파일럿 지표로 수집).

## 4. 결론: **범위 축소 진행**

**판정 근거**
- 정상 주문 경로(주문 감지 → 공급처 발주 → 선충전 결제 → 송장 회수 → 쿠팡 업로드 → 정산 대사)는 **공식 API만으로 구현 가능**하다. "정상 주문은 무개입"이라는 목표는 공급처 API 승인과 결제 검증이 끝나면 달성할 수 있다.
- 다만 다음 세 가지는 원래 기획대로 구현할 수 없거나 투자 대비 효과가 낮다.
  1. **쿠팡 시장 데이터(판매량·경쟁가·아이템위너)**: 공식 API가 없다. 크롤링은 금지 사항이다. → 선정 모델은 네이버 데이터 + 수동 CSV 기반으로 축소하고, auto 선정 모드는 데이터가 쌓이기 전까지 비활성화한다.
  2. **저가(공급가 1만원 이하) 위탁 상품**: 배송비 고정비 때문에 손익분기가가 공급가의 1.5배를 넘는다. 동일상품 경쟁에서 불리하다. → 게이트 기본값을 **공급가 15,000원 이상 또는 묶음 판매로 단가를 높일 수 있는 상품**으로 둔다(config).
  3. **완전 자동 결제**: 도매꾹은 문서상 가능하고 오너클랜은 검증이 필요하다. → 기본 `ORDER_MODE=approve`, `PAYMENT_MODE=approve_tap`으로 시작하고 파일럿 지표로 전환한다.

**P1 착수 전 사용자(사장님)가 해야 할 일 (시스템이 대신할 수 없음)**
1. 사업자등록(일반과세자), 통신판매업 신고, 쿠팡 Wing 입점 [L1·L2]
2. 쿠팡 Wing에서 OPEN API 키 발급 + VPS 고정 IP 등록 / **현행 카테고리 수수료표 확인**(U2) / 판매자 점수 기준 화면 확인(U4) / 판매이용약관의 재판매·개인정보·자동화 조항 확인(U12)
3. **도매꾹 Private API 권한 신청**(주문서 생성·이머니·구매관리), **오너클랜 API 센터 가입 + 샌드박스 접근 확인**. 두 곳의 이미지 사용 허락 범위와 세금계산서 발행 방식 문의(U6·U8·L9)
4. 네이버 개발자센터 앱 등록(데이터랩·쇼핑인사이트·검색), 네이버 검색광고 API 라이선스 발급
5. 개인정보 처리위탁 vs 제3자 제공 판단과 처리방침 고지 방식 확인(L7). 식품·KC 대상 카테고리는 초기 파일럿에서 제외 권장

**Phase 1(설계) 진입 조건**: 위 3번에서 **최소 1개 공급처의 발주 API 사용 권한이 확인될 것**. 승인되지 않으면 발주·결제 판정이 "반자동"으로 떨어지고, 무인 운영 목표를 다시 평가해야 한다.
