# 설계 (architecture.md)

- 작성일: 2026-10-13
- 전제: 사업자등록 ✅, 통신판매업 신고 ✅. 판매채널은 쿠팡(판매자배송), **공급처 API 승인 여부와 무관하게 동작**해야 함.
- 비즈니스 모델: 네이버·도매꾹 등 다른 이커머스 데이터로 상품을 고르고 쿠팡에 등록한다. 쿠팡 주문이 들어오면 원 판매채널에 **고객 배송지로 대신 주문**하고, 그 차액을 수익으로 얻는다.

---

## 1. 배포 형태 결정: **무료 Mac 홈서버(기본) / 고정 IP 리눅스 서버(대안)**

| 후보 | 판단 | 이유 |
|---|---|---|
| 서버리스·무료 PaaS(Vercel·Workers·Render) | ✗ | 나가는 IP가 고정되지 않아 쿠팡 허용 IP(최대 10개)로 등록할 수 없음. 무료 PaaS는 잠들어 주문 수집이 끊김 |
| **Mac 홈서버(launchd)** | ✅ 기본 | 무료이고 부하가 충분히 낮음. 집 공인 IP를 등록하고 변경 시 자동 감지·알림. 내장 PGlite라 Docker 불필요. CI 통과분만 자동 업데이트·롤백 |
| 리눅스 VPS(Oracle Always Free 등) + Docker | ✅ 대안 | 고정 IP가 필요하거나 규모가 커지면 이전(PostgreSQL + GitHub Actions SSH 배포) |

- 단일 프로세스 안에 API 서버·스케줄러·워커를 둡니다(모듈러 모놀리스).
- DB: 홈서버는 PGlite(내장 Postgres), 리눅스 서버는 PostgreSQL. 같은 마이그레이션을 씁니다.
- 관리자 웹: 같은 서버가 React SPA를 서빙합니다. 로그인은 비밀번호 + TOTP이고, 외부 접속은 Tailscale(serve/funnel)을 씁니다.
- 알림: 텔레그램 봇.

## 2. 공급처 API 없이 동작하는 방법 — "구매 대행 작업함(Assisted Purchase)"

공급처에 주문을 넣는 방법을 **전략(PurchaseStrategy)** 으로 분리한다.

| 전략 | 동작 | 사용 조건 |
|---|---|---|
| **assisted (기본값)** | 시스템이 구매 작업을 만든다. 작업에는 원 상품 링크, 옵션, 수량, 예상 원가·마진, 배송지 복사 버튼, 배송메모가 들어간다. 사람이 휴대폰으로 링크를 열어 결제한 뒤 **원주문번호와 실결제금액을 입력**한다. 송장번호도 사람이 입력하며, 공급처 송장 API가 있으면 자동 조회한다 | **모든 공급처**. API 승인이 필요 없다 |
| api | 공급처 발주 API로 자동 주문한다(도매꾹 Private API `setOrder`, 오너클랜 `createOrder` 등) | 해당 공급처 API 승인과 `LIVE_ORDERING=true` |

- **브라우저 자동화로 타 쇼핑몰에 로그인·결제하는 기능은 구현하지 않는다.** 이유는 세 가지다. ① 각 쇼핑몰 약관의 자동화 접근 금지와 계정 정지 위험 ② 캡차·2차인증 우회가 필요해짐 ③ 결제수단 정보를 서버에 저장해야 하는 보안 위험. 무인화의 상한은 "알림 → 1분 내 수동 결제 → 번호 입력"이다.
- 주문 1건당 사람이 하는 일: 알림 탭 → [상품 열기] → 옵션·수량 선택 → [배송지 복사] 붙여넣기 → 결제 → 주문번호·금액 입력(약 1~2분). 송장 입력 약 20초.

### 소스별 역할 (무인 운영 우선순위)

| 소스 | 상품 데이터 | 주문(구매) | 송장 | 이미지 재사용 | 무인 운영 |
|---|---|---|---|---|---|
| **오너클랜** | GraphQL API(본인 계정 ID/PW → JWT): 검색·상세·가격정책(준수가)·재고 | **API 자동 발주**(`simulateCreateOrder` → `createOrder`, 원장주문코드에 멱등키) | **API 자동 조회** | 오픈마켓 판매 가능 상품만 | ✅ 완전 자동(결제가 '미처리'로 남으면 결제 필요 알림) |
| 도매꾹/도매매 | Open API(키만 필요): 가격·재고·KC·고시정보·최저판매준수가·`license.usable` | assisted(Private API 승인 후 api로 교체 가능) | 사람 입력 | `license.usable=true`만 | 반자동(주문당 1~2분) |
| 네이버 쇼핑 | 검색 API(제목·최저가·링크) | assisted | 사람 입력 | **불가**(직접 제작 이미지 필요) | 반자동. 시장 최저가 게이트 때문에 대부분 탈락 |
| 네이버 데이터랩·검색광고 | 추세·검색량(시장 데이터 전용) | — | — | — | — |
| demo / mock | 체험·테스트용 | api / assisted | api | 허용 | — |

**auto 선정 모드는 기본적으로 "API 자동 발주 가능 + 이미지 재사용 가능" 상품만 자동 등록합니다**(`selection.autoListRequiresApiOrder`). 그래서 등록된 상품의 주문은 사람 개입 없이 끝까지 처리됩니다. 사람이 결제해야 하는 상품은 후보 탭에서 직접 승인할 때만 등록됩니다.

## 3. 시스템 구성 (헥사고날 / 포트-어댑터)

```
server/src
├── config/        env(비밀값·플래그) 스키마 + settings(사업 파라미터, DB 저장, 웹에서 수정)
├── db/            Kysely 연결(pg | pglite), 마이그레이션, 테이블 타입
├── lib/           로거(마스킹), PII 암호화, 금액, 시계, rate limiter, http
├── ports/         MarketPort(판매채널), SourceAdapter(공급처), Notifier, TrendProvider …
├── adapters/
│   ├── coupang/   HMAC 서명, HTTP 클라이언트, MarketPort 구현, DRY_RUN 래퍼
│   ├── domeggook/ Open API(상품) + (선택) Private API(발주)
│   ├── naver/     쇼핑검색, 데이터랩, 쇼핑인사이트, 검색광고
│   ├── telegram/
│   └── fake/      FakeMarket, MockSource (테스트·데모)
├── modules/
│   ├── pricing/   손익 계산, 목표 판매가, 가격 변경 가드
│   ├── selection/ 후보 수집 → 신호 → 게이트 → 스코어
│   ├── listing/   상품명·태그 정규화, 금지문구 검사, 쿠팡 페이로드 생성, 등록
│   ├── orders/    주문 상태머신, 폴링, 구매 작업, 송장 업로드
│   ├── sync/      공급가·재고 동기화 → 가격 조정/판매중지
│   ├── guard/     kill switch, 한도, 자동 판매중지 규칙
│   ├── finance/   주문별 손익, 정산 대사
│   └── reports/   일일 리포트
├── jobs/          스케줄러(주기 작업 등록, 실행 이력, 중복 실행 방지)
├── http/          Fastify 라우트(auth, dashboard, orders, candidates, listings, settings)
└── app.ts / main.ts  조립(composition root) — 어댑터 선택은 여기서만
web/               React 관리자 화면
```

**변경 용이성 원칙**
1. 모듈은 **포트(인터페이스)에만 의존**한다. 쿠팡·도매꾹 사양이 바뀌면 어댑터 파일만 고친다.
2. 판매채널을 추가하려면(예: 스마트스토어) `MarketPort` 구현을 하나 더 만든다. 공급처를 추가하려면 `SourceAdapter`를 구현해 레지스트리에 한 줄 등록한다.
3. 수수료·마진·한도·금지문구·주기는 **settings 테이블**에 둔다(기본값은 코드에 출처·확인일 주석과 함께). 관리자 웹에서 수정하고, 재배포는 필요 없다.
4. 상태머신 전이는 **선언적 표 하나**(`orders/stateMachine.ts`)로 관리한다.
5. 모든 외부 부작용은 `DRY_RUN` 래퍼를 통과한다. 기능별 플래그는 `LIVE_LISTING`, `LIVE_ORDERING`, `LIVE_CS`, `LIVE_PRICING`이다.
6. 스키마 변경은 번호가 붙은 마이그레이션 파일로만 한다.

## 4. 주문 상태머신 (`server/src/modules/orders/stateMachine.ts` 표 하나로 관리)

```
NEW ─(매핑·재고·가격 재확인, 마진/한도 가드, 쿠팡 상품준비중 처리 + 배송지 재조회)─┬→ PURCHASED   (API 자동 발주)
                                                                              ├→ PAYMENT_PENDING (주문 생성, 결제 필요)
                                                                              └→ AWAITING_PURCHASE (사람 구매)
PURCHASED ─(송장: 공급처 API 자동 조회 또는 사람 입력 → 쿠팡 업로드)→ TRACKING_UPLOADED → IN_TRANSIT → DELIVERED ─(정산 대사)→ SETTLED
예외: OUT_OF_STOCK · MARGIN_NEGATIVE · LIMIT_EXCEEDED · SOURCE_ERROR(자동 재시도 6회) · MANUAL_REVIEW
      CANCEL_REQUESTED · CANCELLED · RETURN_REQUESTED · RETURNED · SHIPPING_DELAYED · ADDRESS_CHANGED
```
- **상품준비중 처리를 발주 전에 합니다**: 고객이 즉시 취소할 수 없게 해서 "발주했는데 취소됨"을 줄이고, 결제완료 단계에서 바뀐 배송지를 처리 직후 재조회해 반영합니다(쿠팡 문서 권고).
- 멱등성: `(market, shipmentBoxId, vendorItemId)` 유니크, 상태 전이는 낙관적 잠금(이전 상태 조건부 UPDATE), 공급처 발주는 멱등키 `cp-{orderId}-{vendorItemId}`(오너클랜은 원장주문코드로 기존 주문 검색 후 생성).
- **품절·마진역전이어도 자동 취소하지 않습니다**(판매자 강제취소는 판매자점수 하락이 API 문서에 명시됨). 상품을 즉시 판매중지하고 알림을 보냅니다.
- 구매 전 고객 취소는 자동으로 CANCELLED 처리하고(구매 불필요), 구매 후 취소는 CANCEL_REQUESTED와 알림으로 넘깁니다.

## 5. 가격·마진 (feasibility.md 2-1 공식)
`P = S·(10/11 − c − r) − (C + D)·10/11` (일반과세자, 매입 세금계산서 수취 가정). 소스가 간이과세자·개인판매자처럼 세금계산서가 없으면 `inputVatDeductible=false`로 바꿔 계산한다(이때 공급가 VAT 공제 없음).
- 목표 판매가 = max(최소이익 기준가, 최소이익률 기준가, 최저판매준수가) → 100원 단위 올림.
- 경쟁가(네이버 최저가 등)가 목표가보다 낮으면 게이트에서 탈락한다.
- 가격 변경: 하루 최대 횟수, 1회 최대 변동률(쿠팡 −50%/+100% 범위 내)을 지키고, 하한 미만으로는 절대 내리지 않는다.

## 6. 보안·개인정보
- 비밀값은 env로만 받고 로그에 남기지 않는다(pino redact).
- 수취인 이름·전화·주소는 AES-256-GCM으로 컬럼 암호화(`PII_KEY`). 화면에서는 기본 마스킹, 구매 작업 화면에서만 복호화 표시하고 열람 로그를 남긴다.
- 배송완료 후 `PII_RETENTION_DAYS`(기본 90일)가 지나면 PII 컬럼을 파기한다. 주문·금액 기록은 전자상거래법상 보존기간 동안 유지한다.
- 관리자 로그인: scrypt 해시 + TOTP, 세션 쿠키(HttpOnly, SameSite=Strict), 로그인 시도 제한, 접근 로그.

## 7. 구현하지 않는 것 (금지 사유)
1. 쿠팡에서 구매한 상품을 쿠팡에 재판매하는 경로: 쿠팡 정책상 금지 전제. `SourceAdapter` 레지스트리에 쿠팡을 소스로 등록할 수 없게 막는다.
2. API 없는 쇼핑몰 브라우저 자동 로그인·결제, 캡차 우회: 약관 위반, 계정 정지, 결제정보 보안 위험.
3. 쿠팡/Wing 페이지 서버 크롤링: 계정 정지 위험.
4. 타 판매자 상세페이지 이미지·문구 복제: 저작권. 네이버 소스 상품은 직접 제작한 이미지가 없으면 등록 게이트에서 막는다.

## 8. 운영 흐름 (하루 5분 목표)
- 텔레그램 "구매할 주문 N건" → 웹 작업함에서 건당 1~2분.
- 송장 입력: 원 쇼핑몰 주문내역에서 복사해 붙여넣기(20초).
- 일일 리포트(09:00): 어제 매출·이익, 미처리 작업, 예외, 품절·가격변동, 키 만료 D-day.
- 주 1회: 후보 승인(10분), 예치금·카드 한도 점검.
