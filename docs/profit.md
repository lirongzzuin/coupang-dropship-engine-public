# 수익 극대화 설계 (profit.md)

- 작성일: 2026-10-13
- 코드 위치: `modules/pricing/pricing.ts`(가격 함수), `modules/listing/items.ts`(옵션·재가격), `modules/sync/service.ts`(최적화·원가 탐색), `modules/finance/service.ts`(수수료 학습·상품별 이익)

## 1. 근거
- 쿠팡 아이템위너(동일상품 대표 노출)는 **판매가+배송비 최저**를 중심으로, 단위가격·재고·출고소요일·판매자점수를 함께 봅니다. 산정식은 비공개입니다. [2차] [windly](https://www.windly.cc/blog/coupang-item-winner-exposure-restriction), [온채널](https://onchannelnotice.oopy.io/71f8ef33-fca0-40bb-909e-1d86e6de5a55)
- 위탁 상품은 같은 도매 상품을 여러 판매자가 올립니다. 그래서 **경쟁가 바로 아래 가격**을 지키면서 남는 마진은 최대한 가져와야 합니다.
- 경쟁가를 항상 알 수는 없습니다. 네이버 쇼핑 API는 종료됐고 쿠팡 파트너스는 선택 사항입니다. 그래서 **실제 판매 결과로 가격을 학습**합니다.

## 2. 가격 모델
```
옵션별 하한가 floor_n = 최소 이익·이익률·최저판매준수가를 만족하는 최저 판매가(n개 묶음, 배송비 1회)
판매가_n       = 끝자리(floor_n × (1 + markup))      # 상품 하나에 markup 하나 → 모든 옵션이 같이 움직임
끝자리         = 1만원 이상 ○,900원 / 미만 ○○90원 (항상 올림)
```
- **목표 마크업(중간 지점)**: 경쟁 최저가(쿠팡 파트너스 → 11번가 순)를 알면 `(경쟁가 × 0.99 / floor − 1) × gapCapture(50%)`입니다. 경쟁가 바로 아래가 아니라 **하한가와 경쟁가의 중간**입니다. 경쟁가를 모르면 15%이고, 범위는 0~30%입니다.
- **출시 가격**: 등록 후 `launchDays`(10일)는 `launchMarkup`(5%)으로 팝니다. 신규 상품은 초기 판매·리뷰가 쿠팡 노출을 좌우하기 때문입니다.
- **하한 엄수**: 어떤 경우에도 판매가 < floor_n이 되지 않습니다. 원가가 오르면 하한도 다시 계산합니다.
- **안전장치**: 1회 변동률(내림 20%, 올림 50%)과 상품당 하루 변경 횟수를 제한합니다. 쿠팡 API 한도(−50%/+100%)보다 보수적입니다.

## 3. 가격 자동 최적화 (매일, `profit.optimize`)
마지막 가격 변경 후 `observeDays`(3일)가 지나면 그 가격 구간의 성과로 판단합니다.

| 상황 | 동작 |
|---|---|
| 출시 기간(10일) | 변경 없음 |
| 출시 끝, 판매 1건 이상 | 목표 마크업(중간 지점)으로 이동, 출시 가격을 최고 기록으로 저장(안 팔리면 복귀) |
| 주문 ≥ `raiseMinOrders`(2)인데 직전 같은 기간보다 판매가 `velocityGuard`(80%) 미만 | 인상 보류(판매 속도 보호) |
| 주문 ≥ `raiseMinOrders`(2) | 지금 하루 이익이 최고 기록이면 기록 → 마크업 +3%p (경쟁가·상한 이내) |
| 주문은 있으나 하루 이익 < 최고 기록 × 60% | 최고 기록 마크업으로 복귀 |
| `noSaleDays`(5) 동안 0건 | 올렸다가 안 팔린 거면 최고 기록으로 복귀, 아니면 −4%p (0까지) |
| 마크업 0(하한가)에서도 14일 0건 | 판매종료 → 다음 선정에서 새 상품으로 교체 |

## 3-1. 배송비 반영(점검 2026-10-13)
- 쿠팡에는 **무료배송**으로 올립니다. 공급처 배송비는 하한가 계산에 들어가므로 판매가에 포함됩니다.
- 도매꾹 배송비는 형식에 따라 이렇게 읽습니다.
  - 고정배송비: `fee` 값
  - 수량별비례: `tbl` 값(예: "10+3000" = 10개까지 한 상자 3,000원)
  - 무료배송: 0원
  - 이전에는 수량별비례를 0원으로 잘못 읽었습니다.
- 여러 개를 팔면 배송비를 이렇게 계산합니다.
  - 묶음배송이 안 되는 상품: 개수만큼
  - 상자당 수량 한도가 있는 상품: 상자 수만큼
- 제주·도서산간은 배송하지 않습니다(`remoteAreaDeliverable=N`). 그래서 추가 배송비가 생기지 않습니다.
- 반품 비용은 판매가의 3%를 충당금으로 떼어 둡니다. 단순변심 반품비는 고객에게 받습니다.
- 기본 이익 기준: 최소 순이익 3,000원, 최소 이익률 12%

## 4. 묶음 수량 옵션
- 공급처가 여러 개를 **배송비 1회**로 보낼 때만 1개·2개·3개 옵션을 만듭니다.
  - 오너클랜: `boxQuantity` 이내
  - 도매꾹: 수량별 배송비 구간이 없고 묶음배송이 가능할 때
- 배송비가 한 번만 들어 **개당 가격이 낮아지고(단위가격 유리) 객단가가 올라갑니다.** 쿠팡 `unitCount`로 개당 단가를 표시합니다.
- 주문이 들어오면 `주문수량 × 묶음수량`만큼 공급처에 발주하고, 원가·이익도 그 기준으로 계산합니다.

## 5. 원가 절감·수수료 학습
- **원가 탐색(7일마다)**: 같은 공급처에서 상품명이 같은(다른 판매자 복제) 더 싼 상품을 찾아, 원가가 3% 이상 싸고 재고·최소주문이 맞으면 공급처 상품을 자동으로 교체합니다. 교체 후 가격을 다시 계산하고 알림을 보냅니다.
- **실수수료 학습**: 쿠팡 정산의 `서비스이용료 ÷ 매출금액`을 상품별 지수평균으로 저장합니다. 이후 하한가·손익 계산에서 카테고리 표 대신 이 값을 씁니다.

## 6. 이익 중심 선정·보고
- 점수에 **이익 잠재력 = log(개당 이익 × 월 검색량)**을 추가했습니다(가중치 0.2). 이익률이 높아도 팔리지 않을 상품보다 돈이 되는 상품이 우선입니다.
- 대시보드에 **상품별 이익(최근 30일)**, 일일 리포트에 **최근 7일 이익 TOP 3**를 보여줍니다.

## 7. 수익과 상품성의 균형
이익만 보고 값을 올리면 판매가 끊겨 결국 이익이 0이 됩니다. 그래서 아래 원칙을 둡니다.
- **가격**: 경쟁가 바로 아래까지 올리지 않고 중간 지점을 목표로 합니다(상한 30%). 출시 기간에는 싸게 팔고, 인상은 판매 속도가 유지될 때만 합니다. 올린 뒤 이익이 줄면 최고 기록으로 돌아갑니다.
- **상품 선정(상품성)**:
  - 탈락 기준
    - 출고 준비일이 `maxPrepDays`(3일)를 넘는 상품. 도착이 늦으면 구매 전환과 판매자 점수가 떨어집니다.
    - 판매자 만족도가 `minSellerScore`(85%) 미만인 공급자. 후기 10건 이상일 때만 판단합니다.
  - 가점
    - 빠른 출고: 1일 이하 1.0, 2일 0.6, 3일 0.3
    - 이미지 수: 5장 이상이면 만점
    - 반품 가능
    - 낮은 진입장벽: 상위 경쟁 상품의 쿠팡 리뷰 수가 적을수록 유리(리뷰 CSV를 가져온 경우)

## 8. 하지 않은 것(이유)
| 항목 | 이유 |

| 정가 부풀리기로 할인율 표시 | 허위 할인 표시 위험. `originalPriceMultiplier=1` 유지 |
| 쿠팡 광고 자동 집행 | 비용이 들고 API 범위 밖. 수익 데이터가 쌓인 뒤 별도 검토 |
